# Release checklist

Everything App Store Connect asks for, matched to what Morsel actually does. Architecture and the
per-feature contract are in [`../ARCHITECTURE.md`](../ARCHITECTURE.md); what leaves the device is in
[`AI_AND_DATA.md`](AI_AND_DATA.md). Status column: tick as you go.

## 0. Prerequisites

- [ ] Apple Developer Program active; `DEVELOPMENT_TEAM` committed in `project.yml` (see `BUILD.md` path C).
- [ ] App ID `com.ashtonkirkman.morsel` registered; app record "Morsel" created in App Store Connect.
- [ ] Proxy deployed and its URL is the default in the app, or the app ships with clear "enter your proxy
      URL / API key" onboarding (App Review will reject an app whose core feature needs a setup step
      they cannot complete; supply a demo proxy URL in the Review Notes).
- [ ] CI green on `main`.

## 1. Build metadata

- [ ] `MARKETING_VERSION` = `1.0.0`, `CURRENT_PROJECT_VERSION` bumped.
- [ ] App icon: `AppIcon-1024.png` present, no alpha channel, no rounded corners (Apple masks it).
      Regenerate with `make icon`.
- [ ] `ITSAppUsesNonExemptEncryption: false` is already set (HTTPS only), so no export-compliance
      questionnaire.
- [ ] Deployment target iOS 17.0; iPhone only (`TARGETED_DEVICE_FAMILY: "1"`), portrait only.

## 2. Permission strings (Info.plist, generated from `project.yml`)

Both are already in `project.yml`; re-read them before each release so they match current behaviour.

| Key | Current text | Triggered by |
|---|---|---|
| `NSCameraUsageDescription` | "Morsel uses the camera to scan barcodes and photograph meals so it can log calories for you." | Snap meal, Scan barcode |
| `NSPhotoLibraryUsageDescription` | "Morsel can estimate calories from meal photos you pick from your library." | Snap meal > choose from library |

- [ ] The app must request each permission only when the user starts that flow, never at launch.
- [ ] Denied permission shows an inline explanation with a button to Settings (not a dead end).

## 3. Privacy manifest and App Privacy answers

`Morsel/Resources/PrivacyInfo.xcprivacy` declares what the App Privacy "nutrition label" must repeat.
Answer the questionnaire in App Store Connect > App Privacy exactly like this:

| Question | Answer |
|---|---|
| Do you collect data from this app? | **Yes** |
| Photos or Videos | Collected. Purpose: App Functionality. **Not** linked to the user. **Not** used for tracking. (Meal photos are sent to the Anthropic API via the proxy for calorie estimation and are not stored server-side by Morsel.) |
| Other User Content | Collected. Purpose: App Functionality. Not linked, not tracking. (Optional hint text with a photo; barcodes and search terms sent to Open Food Facts.) |
| Health & Fitness | **Not collected.** Calorie logs, goals and body stats stay on the device (SwiftData + UserDefaults) and are never uploaded. If you later add iCloud sync or Apple Health, revisit this row. |
| Contact info, Identifiers, Usage data, Diagnostics, Location, Purchases | Not collected. |
| Tracking (ATT) | **No.** `NSPrivacyTracking` is false; no ad SDKs, no analytics. |

- [ ] Required-reason APIs: UserDefaults `CA92.1`, file timestamps `C617.1`. If a feature starts using
      `systemUptime`, disk space or active-keyboard APIs, add the category and reason to the manifest.
- [ ] Privacy policy URL (mandatory). Publish `AI_AND_DATA.md` content as a page (GitHub Pages is fine)
      and paste the URL into App Store Connect **and** into Settings > About inside the app.
- [ ] Third parties named in the policy: Anthropic (photo + hint text), Open Food Facts (barcodes, search
      text), Cloudflare (the proxy host, sees the request in transit). Link their policies.

## 4. AI-generated content disclosure

App Review guideline 5.1.1 / 1.2 and the App Store's AI expectations:

- [ ] The photo flow labels estimates as AI-generated (the `ConfidenceBadge` plus the wording
      "Estimate", never "Measured").
- [ ] User can edit every AI-produced value before it is logged (one confirm tap, but always editable).
- [ ] App description contains a sentence like: "Photo estimates are generated by an AI model and can be
      wrong; check them before relying on them for medical decisions."
- [ ] Nothing in the UI or metadata claims medical accuracy or offers diagnosis. Morsel is a logger,
      not a medical device; keep it out of the Medical category.
- [ ] Review Notes: explain the AI feature, that images are sent to Anthropic through a proxy the
      developer runs, and give the reviewer a working configuration.

## 5. Age rating and category

- [ ] Category: **Health & Fitness** (secondary: Food & Drink).
- [ ] Age rating questionnaire: no objectionable content, no unrestricted web access, no gambling,
      no user-generated content shared with others. Expected result: **4+**. Apple's rating
      questionnaire changed in 2025 (adds 13+/16+/18+ tiers); answer honestly and expect 4+.
- [ ] If you ever add a community/sharing feature, revisit UGC moderation requirements.

## 6. Store listing

- [ ] Name "Morsel" (30 chars max), subtitle e.g. "Calories from a photo" (30 chars).
- [ ] Description, keywords (100 chars), promotional text.
- [ ] **Support URL** (mandatory): a GitHub Discussions/Issues page or a simple page with an email.
- [ ] Marketing URL (optional) and Privacy Policy URL (mandatory, see section 3).
- [ ] Copyright: "2026 Ashton Kirkman".
- [ ] Contact info for App Review + demo account fields ("not required, no login").

## 7. Screenshots

Required sizes for iPhone-only apps (App Store Connect accepts the largest and scales down, but
provide at least):

| Display | Pixels (portrait) | Devices |
|---|---|---|
| 6.9" | 1320 x 2868 | iPhone 16 Pro Max / 17 Pro Max |
| 6.5" or 6.7" | 1284 x 2778 or 1290 x 2796 | iPhone 14/15 Plus, 15 Pro Max |

Take them in the Simulator (`Cmd+S`) on those devices with seeded demo data; the status bar is fine.
Suggested set (max 10): Today ring with a full day logged; photo flow showing the clarifying
question; the review sheet with confidence badge; barcode result; search + favorites; History chart;
Settings/goals; dark mode of Today.

- [ ] No device frames required; no text overlays needed for 1.0.
- [ ] Screenshots show real UI only (no mock-ups of unshipped features).

## 8. Pre-submission smoke test (on a physical phone)

- [ ] Fresh install > onboarding > Mifflin-St Jeor goal computed > Today shows the ring.
- [ ] Snap a meal (camera) and pick from library; answer the clarifying question; log; undo toast works.
- [ ] Scan a real barcode found on Open Food Facts and one that is not (graceful "not found").
- [ ] Search, favorite, use recents, quick add.
- [ ] Airplane mode: every network path shows the plain-English error with retry, nothing crashes.
- [ ] History charts across day/week/month; CSV export produces a file that opens in Numbers/Excel.
- [ ] Dark mode, largest Dynamic Type size, VoiceOver on icon-only buttons.
- [ ] Kill and relaunch: data persists; photo thumbnails load.

## 9. Tagging and shipping 1.0

```bash
git checkout main && git pull
# bump MARKETING_VERSION / CURRENT_PROJECT_VERSION in project.yml, commit
git tag -a v1.0.0 -m "Morsel 1.0.0"
git push origin main --tags
# on the Mac:
bundle exec fastlane beta            # or Xcode > Product > Archive > Distribute
```

- [ ] TestFlight internal testing for at least a few days on your own phone.
- [ ] Submit for review with "Manually release this version" so the tag, the build and the store
      release line up.
- [ ] After approval: GitHub Release from the tag with the CHANGELOG excerpt; note the App Store link
      in `README.md`.

## 10. Post-1.0 hygiene

- [ ] Rotate the Anthropic key in the proxy if it was ever pasted into a chat, log or screenshot.
- [ ] Set a monthly spend limit on the Anthropic console (see `AI_AND_DATA.md` for per-photo cost).
- [ ] Watch crash reports in Xcode Organizer for the first week.
